# Local self-use iteration, 2026-10-30

This iteration uses isolated local workflows and an actual terminal rather than recruited users.
It makes no model calls and consumes none of the previously exhausted 20-session authorization.
The new behavior remains unreleased on main until real-agent validation is authorized and run.

## What was exercised

- In a real PTY: selected a file, opened its change history, inspected the diff, previewed recovery,
  explicitly confirmed it, and verified restored content, a recorded recovery and a clean inbox.
- Project filtering separates repository files and their Claude auto memory from other projects.
  Shared user context has an explicit global terminal view.
- Pagination reaches records older than 200 changes; summary counts cover the whole selection.
- Search treats SQL wildcard characters literally, and a finding in another change cannot be
  dismissed from the currently opened change.
- A real local subprocess writes context and either exits successfully or fails. The hook handlers
  capture its start state and emit an immediate review notice after either result.
- Creation, deletion, setting changes and restoration preserve content and captured permissions.
  Irrelevant config counters and unmodified commands stay quiet.
- Concurrent shell tools retain separate start states. A version already recorded by a Write/Edit
  hook keeps its observed attribution and is not counted again as an external change.
- Start-state capture and schema upgrades roll back on interruption. Captured objects survive GC.
  A capture error does not weaken an existing ask decision; missing start state remains a visible
  hook failure. Cwd changes retain the original observation scope.

## Boundaries

Hook events are delivered by this local harness, not by a real Claude Code session. Actual client
registration and terminal rendering still require real-agent validation. The new demo exercises
the success interval and recovery through the real hook handlers, without loading a model.
Detached background changes and transient writes reverted before completion are not observed.
The before/after interval never proves which process wrote the content. This is workflow and
regression evidence, not user-retention or broad attack-prevention evidence.

The seven 100-sample latency cases passed their P95 budgets. The complete ordinary Bash pre/post
pair measured 120.6 ms P95; 1,000 active memory files plus 1,000 unrelated files measured 237.9 ms.
See [latency details](../../bench/HOOK_LATENCY.md).
